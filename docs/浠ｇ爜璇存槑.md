# 代码说明

工程图纸生成系统：钉钉工号登录 → 任务五步向导 → 合成公司图框工程图 → 预览/下载 DXF。

## 仓库结构

```text
eng-drawing-system/
├── eng-backend/                 # Java 后端（Maven 多模块）
│   ├── eng-admin/               # 启动入口、配置、打包 jar
│   ├── eng-biz/                 # 业务：Controller / Service / 工程图核心
│   └── eng-common/              # 公共：R<T>、异常、工具等
├── eng-frontend/                # Vue3 前端（Vite）
├── docs/
│   ├── sql/init.sql             # 空库初始化
│   └── deploy/docker/prod/      # 生产编排（backend / frontend / paddle-ocr）
├── scripts/check-eng-deps.sh    # 依赖自检（macOS/Linux）
└── data/eng-drawing/            # 运行时数据目录（默认，可配置）
```

| 端 | 技术栈 | 默认端口 |
|----|--------|----------|
| 后端 | Java 17、Spring Boot 3.5、MyBatis-Plus | **6053** |
| 前端 | Vue 3、Ant Design Vue 4、Vite 6、Pinia、Three.js | **8893** |
| 数据库 | MySQL，库名 `eng_drawing` | 示例 `23306` |

统一返回体：`R<T>`。包名：`org.nineai`（工程图核心在 `org.nineai.engdrawing`）。

## 后端要点

启动类：`eng-backend/eng-admin/.../EngDrawingApplication.java`  
配置：`application.yml`（端口、上传、ai-drawing）+ `application-dev.yml`（本地数据源，profile 默认 `dev`）。

| 模块路径 | 职责 |
|----------|------|
| `controller/` | HTTP 接口：登录用户、任务、语料、模型配置、日志、健康检查 |
| `service/` | 业务编排 |
| `entity/` + `mapper/` | 表实体与 MyBatis-Plus |
| `engdrawing/` | 图纸核心：抽取、层次、翻译、合成、OCR/LLM 调用、任务槽 |

主要接口前缀（前端经 `/api` 代理后去掉前缀）：

| 前缀 | 说明 |
|------|------|
| `/auth/**` | 登录、用户、改密 |
| `/tasks/**` | 任务 CRUD、上传 STP/DWG、完成、结果/DXF 下载 |
| `/ai-drawing/**`（及任务内嵌调用） | 预览抽取、层次、合成等重逻辑 |
| `/system/glossary` | 语料 |
| `/system/llm-configs` | 模型配置（管理员） |
| `/system/operation-logs`、`/system/runtime-logs` | 日志（管理员） |
| `/health` | 健康检查 |

LLM：库表 `eng_llm_config` 中 **启用的一条** 优先；无启用项时回退 `application.yml` 的 `ai-drawing.deepseek-*`。

## 前端要点

| 路径 | 职责 |
|------|------|
| `src/api/` | 唯一 HTTP 出口（axios），开发时请求 `/api` → 代理到 `6053` |
| `src/views/` | 页面：登录、任务列表、工作台、结果、系统管理 |
| `src/layouts/MainLayout.vue` | 主布局与侧栏 |
| `src/stores/` | 登录态等 |
| `src/router/` | 路由；`adminOnly` 仅管理员 |

主要页面：

| 路由 | 页面 |
|------|------|
| `/login` | 登录 |
| `/tasks` | 任务列表 |
| `/tasks/:id` | 工作台（向导①～⑤） |
| `/tasks/:id/result` | 结果预览/下载 |
| `/system/*` | 用户 / 语料 / 模型 / 日志 |

## 业务主流程（①～⑤）

| 步 | 内容 |
|----|------|
| ① 抽取 | 上传客户 DWG → 预览 → 截图/自动抽取 NOTE、材料 |
| ② 层次 | 上传 STP → Z 展开与旁注 → 保存层次资产（可跳过） |
| ③ 材料 | 3D 旁注与 2D 材料对照确认 |
| ④ 翻译 | NOTE/材料中英审校（语料 + 可选 LLM） |
| ⑤ 生成 | 公司图框合成 → 完成任务 → 结果页下 DXF |

任务元数据在 MySQL；文件落在 `ai-drawing.storage-dir`（默认相对路径 `data/eng-drawing`，相对**后端进程 cwd**；建议用环境变量 `AI_DRAWING_DIR` 指到仓库下该目录的绝对路径）。

开发联调：前端 `vite.config.ts` 把 `/api` 代理到 `http://localhost:6053` 并去掉 `/api` 前缀，故本地只需两边默认端口，不必改前端 `baseURL`。

## 外部依赖（与代码的关系）

| 依赖 | 代码中的用途 |
|------|----------------|
| ODA File Converter | DWG → DXF（`ai-drawing.oda-converter` / 环境变量 `AI_DRAWING_ODA`） |
| Python3 + ezdxf（及 matplotlib） | 版式合成、层次 DXF、预览渲染 |
| PaddleOCR HTTP 服务 | 图纸 OCR（`ai-drawing.ocr-base-url`） |
| OpenAI 兼容 LLM | 视觉抽取辅助、NOTE/材料翻译 |

生产编排真源：`docs/deploy/docker/prod/`。环境安装与启动见 **`docs/环境搭建.md`**。
