# 环境搭建

按本文准备本机环境后，用仓库根目录 **`README.md`** 中的命令启动前后端。代码结构见 **`docs/代码说明.md`**。

**能力分层（避免误解）：**

| 目标 | 最低需要 |
|------|----------|
| 后端起服 + 前端登录、进任务列表 | JDK、Maven、Node、MySQL（已执行 `init.sql`） |
| 完整①～⑤（抽图 / 层次 / 合成） | 再加 Python+ezdxf、ODA、可达的 OCR；LLM 建议可用 |

## 1. 需要安装的软件

| 软件 | 版本建议 | 用途 |
|------|----------|------|
| JDK | **17+** | 后端 |
| Maven | 3.8+ | 编译/启动后端 |
| Node.js | **18+**（含 npm） | 前端 |
| MySQL | 8.x 推荐 | 业务库 `eng_drawing` |
| Python | 3.9+ | 合成脚本（Windows 命令名常为 `python`） |
| ODA File Converter | 官方安装包 | DWG→DXF（无则无法做抽取/合成） |
| PaddleOCR 服务 | HTTP 接口 | 开发默认 `http://127.0.0.1:8868`（可指向已有服务） |

可选：Git、IDE（IntelliJ / VS Code）、Docker（仅自建 OCR 时用）。

## 2. Python 依赖

```bash
pip install "ezdxf>=1.1.0" "matplotlib>=3.7.0"
```

后端默认调用命令名为 **`python3`**（见 `ai-drawing.python`）。  
**Windows 多数环境没有 `python3` 命令**，启动后端前必须设置其一：

```bat
set AI_DRAWING_PYTHON=python
```

```powershell
$env:AI_DRAWING_PYTHON="python"
```

或在 `eng-backend/eng-admin/src/main/resources/application.yml` 改 `ai-drawing.python: python`。

自检：`python -c "import ezdxf, matplotlib; print('ok')"`（或 `python3 -c ...`）。

## 3. MySQL

1. 启动 MySQL。配置文件默认端口是 **`23306`**（历史 Docker 映射），本机常见是 **`3306`**。
2. 若用 3306，任选其一：
   - 环境变量：`MYSQL_PORT=3306`（还可设 `MYSQL_HOST` / `MYSQL_USER` / `MYSQL_PASSWORD`）
   - 或改 `eng-backend/eng-admin/src/main/resources/application-dev.yml` 里的端口
3. 在**仓库根目录**执行空库初始化（**有业务数据的库不要重跑**）：

```bash
# macOS / Linux（端口改成你的）
mysql --default-character-set=utf8mb4 -uroot -proot -h127.0.0.1 -P23306 < docs/sql/init.sql
```

```bat
REM Windows CMD（端口改成你的）
mysql --default-character-set=utf8mb4 -uroot -proot -h127.0.0.1 -P23306 < docs\sql\init.sql
```

脚本会建库 `eng_drawing`、表结构、默认管理员 `admin` / `admin@123`，以及两条 LLM 配置。

后端本地数据源文件：`application-dev.yml`（`spring.profiles.active=dev` 已在 `application.yml` 开启）。

## 4. ODA File Converter

| 系统 | 建议 |
|------|------|
| macOS | 将 `ODAFileConverter.app` 放到仓库 `data/eng-drawing/tools/`，或安装到 `/Applications`，或设 `AI_DRAWING_ODA`（绝对路径） |
| Linux | 可执行文件如 `/opt/oda/ODAFileConverter`，或设 `AI_DRAWING_ODA` |
| Windows | 安装官方 Windows 版后设 `AI_DRAWING_ODA` 指向 `.exe` 绝对路径 |

配置项：`ai-drawing.oda-converter`（空则按代码约定向上查找 `data/eng-drawing/tools/...`）。  
**最稳妥：始终设绝对路径环境变量 `AI_DRAWING_ODA`。**

macOS / Linux 可在仓库根目录执行：

```bash
bash scripts/check-eng-deps.sh
```

## 5. 业务数据目录（重要）

配置项 `ai-drawing.storage-dir` 默认相对路径 `data/eng-drawing`，相对**后端进程当前工作目录**解析。  
从 `eng-backend` 目录执行 `mvn ... spring-boot:run` 时，数据会落在 `eng-backend/data/eng-drawing`，而不是仓库根下的 `data/eng-drawing`。

推荐启动前固定绝对路径：

```bash
export AI_DRAWING_DIR="/绝对路径/eng-drawing-system/data/eng-drawing"
mkdir -p "$AI_DRAWING_DIR"
```

```bat
set AI_DRAWING_DIR=D:\绝对路径\eng-drawing-system\data\eng-drawing
```

## 6. OCR（PaddleOCR）

- 开发默认：`http://127.0.0.1:8868`（`ai-drawing.ocr-base-url`）
- 本机自建：进入 `docs/deploy/docker/prod/paddle-ocr/`，按该目录 `docker-compose-paddle-ocr.yml` 构建启动（需 Docker，首次拉模型较慢）
- 也可用已有 OCR：设 `AI_DRAWING_OCR_BASE_URL=http://主机:端口`

无 OCR 时：**不影响登录与起服**；① 抽取会失败或能力受限。

## 7. LLM（可选但推荐）

- 管理界面：**系统管理 → 模型配置**（仅管理员）
- 默认两条由 `init.sql` 写入：`qwen3.5-397b`（启用）、`lyauto`（未启用）
- 运行时优先用库内启用项；否则回退 `application.yml` 的 `ai-drawing.deepseek-*`
- 无可用模型时：仅靠语料做翻译，视觉相关能力会弱化

请确认本机能访问配置中的 Base URL（如 `10.0.2.77`、`10.64.10.48`）。内网不通时可在「模型配置」改成可达的 OpenAI 兼容地址。

## 8. 启动与验收

端口：**后端 6053**、**前端 8893**。命令见根目录 `README.md`（含 Windows）。顺序：**先后端，后前端**。

验收清单：

1. `http://127.0.0.1:6053/health` 有响应  
2. 浏览器打开 `http://127.0.0.1:8893`，用 `admin` / `admin@123` 登录  
3. 「模型配置」能看到默认模型（内网可达时可点「测试」）  
4. 新建任务能进工作台；配齐 ODA/Python/OCR 后再跑①～⑤  

日志目录默认相对进程 cwd 的 `./logs`（可用 `LOG_PATH`）。  
业务文件见上文「业务数据目录」。

## 常见卡住点

| 现象 | 处理 |
|------|------|
| 后端连不上库 | 核对 MySQL 是否启动；`23306` vs `3306`；账号密码是否与 `application-dev.yml` / 环境变量一致 |
| Windows 合成报找不到 python3 | 设 `AI_DRAWING_PYTHON=python` |
| 上传 DWG 提示需要 ODA | 设 `AI_DRAWING_ODA` 为可执行文件绝对路径 |
| 前端页面开了但接口全失败 | 确认后端已在 6053 监听；前端必须用 `npm run dev`（自带 `/api` 代理），不要只打开静态 dist |
| OCR / LLM 超时 | 检查 `8868` 与模型 Base URL 网络是否通 |

## 9. 生产（简述）

编排与配置在 `docs/deploy/docker/prod/{backend,frontend}/`：

- 后端：`Dockerfile`、`docker-compose-backend.yml`、`application-prod.yml`
- 前端：`docker-compose-frontend.yml`、`nginx/default.conf`

按该目录在目标机部署；数据库勿对已有业务库重跑 `init.sql`。
